## 3.3 架构节点视觉系统

采用第一方 [React Flow UI Base Node](https://reactflow.dev/ui/components/base-node) 开源组件结构作为成熟参考：Header 提供清晰的标题、源码命名空间和可用的导航入口；Content 显示可追溯摘要和最多两类可见的 CORE／REUSE／INTENT／REVIEW 标签，其它类别以真实 `+n` 提示；Footer 展示已有待审任务、认领者、展开操作或知识数量。样式沿用 TaskVision 现有低饱和色系和原生 CSS，并按 `apps`、`packages`、`src`、`tests` 等真实代码目录区分少量颜色。**无需额外安装 Tailwind／shadcn，也不会覆盖 VS Code 原生插件的四通道高亮配置。**

原版用户可使用 `概览 / 详情` 和 `进入模块 / 展开` 操作，不需要迁移或重写现有知识数据。相关视觉质量与回归标准见 `agent/node-design-acceptance.md`。

## 3.2 依赖与影响分析（CodeMap 风格）

在项目架构图中**先点模块或文件**，再在“依赖与影响分析”工具条中选择操作：

- **它依赖**：当前模块向外引用的直接依赖。箭头始终是引用方 → 提供方。
- **依赖它**：直接引用当前模块的其它模块，适合修改共享 API 前确定直接调用方。
- **潜在影响**：沿真实源码引用的反方向递归，显示所有可能需要复核的上游模块。直接影响和传递影响分开统计；蓝绿描边表示直接，淡琥珀表示更远层级，其它模块退至背景以保留空间参照。
- **一跳邻域**：同时看直接输入／输出方向；**全图**：取消分析高亮。

切换模式不会重置手动缩放、拖动位置、关系语义筛选；展开模块后会把显示的文件代表视为同一分析中心，不会把自己的子文件误计为影响对象。键盘聚焦节点后按 Enter／Space 也可以选择分析中心。打开连线证据不会清除选中的模块。移动端的源码详情使用抽屉，先点击“关闭面板”返回架构图再操作分析工具。

**可信度边界**：影响表示在当前已索引源码中按静态 import / require / re-export 等可达的*潜在需要复核范围*；不代表函数调用已经发生、程序执行路径、实际破坏，亦不包括无法解析的动态路径或外部依赖。切换关系类型筛选会改变推导的路径；索引被截断时应先完成索引。Agent 使用 MCP `taskvision_snapshot` 获取同一 source→target 边，不能把这些边改称运行时调用。

## 3.1 语义关系图与开源复用

架构图由真实仓库文件／模块构成。箭头由**引用方 A 指向被引用的模块 B**，即 A 依赖 B；不得解释为函数调用、数据流或时间执行顺序。

- 默认顶层为 **汇总模式**，相同方向的模块依赖合并显示总数和关系类别数。需要精读时切换 **分类模式**，会分别显示 `运行时 / 类型 / 再导出 / 动态 / 词法估计` 的颜色与虚实线。
- 点击连接或通过键盘选中连接并按 Enter，可以查看引用数量、分类统计、源码路径、行号、specifier 和具体分析来源。点击某条证据跳转右侧源码。合并关系会披露被省略的超过 40 条证据，不修改真实总计。
- 基于 **React Flow + ELK + React Flow Smart Edge v5**；Smart Edge 对节点做 A* 避障，Web Worker 负责路由，无法求路时回退到已有安全线路。移动节点、打开子模块、缩放与轮询不会编造新的代码边。
- `CORE/REUSE/INTENT/REVIEW` 仍然是源码语义标记，显示在节点上。**人工设计意图目前未自动当作代码依赖连线**。
- 开源方案评估见 `agent/semantic-graph-oss-review.md`：LikeC4 关系汇总/层级视图、Code Canvas 源码行锚点和 CodeMap 影响链值得借鉴；D2/TALA 布局仅作为可选离线 A/B，尚未替换 ELK。

## 人类指导与知识复用

网页支持项目级或代码锚点指导，Agent 下一次查询即可读取。直接修改源码注释也会更新索引。网页修改源码时只改指定注释正文，保留文件其余内容，并核对源码指纹；知识卡片编辑使用修订号。多窗口冲突保留草稿，要求重新核对，不静默覆盖。

Agent 新知识为提议，需人类采纳；源码事实、历史导入与人工指导有不同来源和状态。相关代码改变会使旧知识需要复核。上下文查询优先返回匹配的复用候选与适用约束，并披露范围或数量限制。

导出可携带 JSON；导入先预检，显示重复和冲突。仅知识记录能够转入，导入记录不会继承人工批准身份，也不恢复任务租约。源文件指纹不匹配时不得将旧指导伪装为当前事实。当前没有跨设备自动同步。

## 多 Agent 协作与跨会话恢复

任务声明具体文件／目录和前置依赖。认领通过数据库事务协调：重叠有效范围、重复认领和未完成依赖都会拒绝。不同 Git worktree 共享协调状态，各自源码和 Review 仍绑定工作区。

**认领成功后必须持久化私有租约凭证。** Agent 将 taskId、agentId、token、expiresAt、workspaceId 写入当前 worktree 的 `.taskvision/agent-leases/<agentId>.json`，目录权限0700、文件0600。该目录保持 Git 忽略并排除在知识索引之外。不能只依赖模型上下文或本轮解释器变量；续接后读私有文件并 heartbeat 验证，成功交接／释放后删除。禁止把 token 放入源码、知识、回复或证据。

租约是协作约定，不是操作系统锁；它不隔离同一系统用户下任意 shell 进程。TaskVision 不自动启动 Agent、合并分支、执行测试或推送代码。

## 人工 Review

认领时记录范围内代码基线；提交时保存实际前后版本、完整任务范围的哈希及 Agent 报告的证据。网页展示真实差异、源码与证据来源。验收绑定 worktree、Git HEAD 和源码指纹；版本变化后拒绝旧批准。

Agent 可以提交与读取 Review，不能通过 MCP／CLI 自行批准。测试命令和结果文本属于 Agent 报告，服务不将其视为自动证明。历史记录缺少基线或内容超过捕获预算时会明确提示。

### 3.2.1 历史 Review 与可信差异

早期 2.1.0 Review 可能只有提交记录、Agent 自报的测试证据、任务范围和版本哈希，没有真正可核查的认领前源代码基线。升级之后这类记录保留原有 `pending` 状态，但网页会明确显示“历史提交”及其 Git 提交版本、缺少可信前后差异和需要重新提交的原因。**不会通过扫描当前源码伪造过去的差异**，也不会自动替用户批准/拒绝旧 Review。

原始任务范围内的文件可能已经被删除、加入 `.gitignore` 或替换为软链接。服务拒绝展示不符合当前读取策略的历史源码；对拥有完整旧基线的交付，仍允许展示其他安全文件的前后对比，但会阻止整体验收，要求新的交付。对没有任何可信基线的旧记录，接口只返回状态、说明和证据，不进行无意义的全项目源码扫描。

用户可以保留审阅意见并点击“要求修改”，由 Agent 对**当前**源代码重新认领和提交 Review。`人工验收通过` 在缺少可信基线、当前代码变化或历史内容不可完整安全读取时禁用。测试只在临时工程执行审阅决定，真实项目的旧交付不会被自动修改。

## 存储、安全与运行边界

源码注释随 Git 版本化。Git 工程的知识／协调数据库在 Git common directory 的 `taskvision/workspace.sqlite`；普通目录使用 `.taskvision/workspace.sqlite`。旧数据库进行兼容、幂等升级，不覆盖旧 sidecar。网页知识不会自动推送远端。

HTTP 只监听127.0.0.1；校验 Host／Origin，写入需要同源 token；脚本CSP不允许内联或eval。图组件的节点定位需要内联样式。文件接口拒绝路径穿越、软链接、已知秘密文件、忽略文件和二进制／超大内容。这些规则不等同于识别任意源码中的秘密，也不提供互联网身份认证。

单文件读取上限512KiB；默认结构扫描2,000文件，超限显式披露。索引复用未变文件的解析缓存，Review 指纹独立读取实际内容。长期大规模分布式部署、所有语言语义和不同系统的图形宿主仍需各自验证。
